# Carousel release controller (single-lane loop)

vjeux 2026-11-10 07:24: "What's the setup that sends them 3 by 3, I can't see any redstone that would
do that in the image". This part is that setup: it turns the golem pulse from farmopt's pad into
the release of the 3 head carts and the queue's 3-slot advance (ironfarm's register), as real
redstone. Generated by `mctas circuit memory release-gen` (crates/circuit-memory/src/releasegen.rs);
benched by `mctas circuit memory release-bench`.

## Contract (ironfarm, 07:27..08:08)
- In: the golem pulse (10 gt).
- Out:
  - `group`: the release group's controls (slots 15..17) ON at golem + 4 for 34 gt.
  - `adv`: all 18 slot controls ON at start + 38 / + 58 / + 78, 10 gt each, the 3 identical.
- Timing, relative to the previous release start:
  - a pulse < 58 gt after it is merged (no release);
  - 58..92 is held and released at + 92;
  - >= 92 releases at once;
  - no golem: the fallback releases at + 104.

## How it works (215 blocks, box 10x2x32)
- **Timer (TMR).** A 3-comparator countdown ring is refilled to 15 by each release and loses 1 per 6-gt round.
- **BUSY.** Ring level minus a constant 2 (a comparator on a hopper holding 23 items). A repeater squares it, so it blocks any input strength.
- **EXPIRE.** A wall torch on the ring, lit when the ring is empty: the fallback.
- **GO.** Subtract comparator: (golem or held request or EXPIRE) minus BUSY. Its output is the release pulse REL. REL refills the ring, so BUSY cuts it ~10 gt later: one self-timed pulse per release.
- **Held request (REQ).** A waxed copper bulb, read back into GO's input by a comparator.
  - Set: the input's rising edge (subtract comparator: input minus input 6 gt late).
  - Reset: the delay chain's taps at REL + 8 .. + 46, ORed into one continuous line from REL + 12 to + 60. Its rising edge turns REQ off. A rising edge inside it toggles nothing: that is the merge window.
  - While REQ is on, the input stays high, so a second early pulse makes no edge (it can't toggle REQ back off).
- **Delay chain.** REL runs north through 11 repeater stages (stones at + 8 .. + 78).
  - Taps + 8 / + 16 / + 24 plus REL through a diode make the group window.
  - Taps + 38 / + 58 / + 78 make the advance line.

## v1 (2026-11-10 09:40): carousel-release-v1.txt (261 blocks)
Changes from v0, each found while wiring it into ironfarm's loop:
- **No release at power-on.** In v0 the empty ring fired the fallback at once. Now ARMED, a one-repeater loop set by the first golem, gates the fallback.
- **Fixed-length refill.** The refill is a squared 8-gt copy of the release pulse (repeater R_r into a stone, read by the refill comparator, which feeds the ring directly).
  - In v0 the refill was the whole release pulse, and its width varied.
  - A first fix (an edge comparator straight on the release dust) could be cut 2 gt short whenever the input's level changed during the refill: a golem handing over to the held request, or the empty-ring torch lighting as a late golem came in. A held golem then released at + 90.
- **Reset line restored south of every tap.** Consecutive taps reach the bulb at the same distance, so the merge window has no gap.
- **Release pulse 12 gt.** The group window is 36 gt and the advance pulses 12 gt each. ironfarm accepted both (09:31).
- **Timing** (the exact model in release-bench), relative to the previous release start:
  - golem in time: group at golem + 4;
  - held golem: + 92 exactly;
  - fallback: + 106.
- **Bench (10:20):**
  - 100,000 slots × 2 seeds (5/5/10% and 15/15/30% missed/early/doubled): 0 violations;

## The loop wiring (`release-gen --loop <ironfarm's loop file>`; 11:20 on explore/ironfarm a5f46f390)
The generated file is designs/farms/iron/parts/carousel-loop/carousel-single-lane-loop-wired.txt (ironfarm keeps its members.tsv and NOTES rows).
The controller is built into a copy of ironfarm's carousel-single-lane-loop-wip.txt, west of row B (turned 180°); 761 blocks of redstone in all.
- **Release group:** its line feeds the 3 group controls by dust: ON at golem + 4 (= t0) for 36 gt.
- **Advance:** slots 3..17 all on one tick (t0 + 38/58/78, 12 gt): each feeder's delay pads its path to the slowest (row A). The 3 descending tail slots get it 2 gt later, through their own diodes (ironfarm 10:30: fine).
- **Tail windows** (each slot its own net, merged into the 3rd advance), t0-relative: slot 2 OFF at + 100, slot 1 at + 118, slot 0 at + 120 (ironfarm 10:58).
  - Slots 1 and 0: an east-side chain from the delay chain's last advance stone, run under the loop at y -3 and up at x 8; stones at golem + 86/96/104/106. Slot 0's taps go into its x 6 feed line, slot 1's through an OR line along x 10 and the z 24 line.
  - Slot 2: a branch off the y -3 line along x 3, into the support block of slot 2's net.
  - Each net gets the advance through its own diode, so a short window can't leak into a longer one.
- **Stand:** three waxed copper bulb latches.
  - Set at t0 + 6 / + 12 / + 18 (6 apart: ironfarm 10:58).
  - Reset by line 4, 28 gt after the release run's detector rail (-3,1,4) powers. That equals ironfarm's bench + 27: his bench brakes after the tick it reads, so its carts feel bench + N on tick + N + 1. Redstone + 26 behaved like his + 25 and missed a cart.
  - The train's three carts merge in 4 pulse-stretching repeaters; an edge comparator makes one reset per train.
- **Controls:** all 21 glass control blocks become stone.
- **Probe file:** `F.probe.txt` holds the controller alone with the 21 controls as ports. `release-trace F.probe.txt --at <golems> --det <detector ticks>` prints every control's on/off ticks.
- **Cart runs** (`queue-loop-run F --wired=-7,-1,5 --tail-check-at 43`, the golem pulse the only input; the at-rest tail check one tick before the tail moves):
  - 3 seeds × 60 slots: 0 problems; 10 seeds × 300 slots (seeds 11..20): 0 problems.
  - Film (mobviewer, the viewer replaying the bench's drive, all 1,281 cart positions matching): https://artifacts.internalmeta.com/a/2697218614068712
  - Wired = the controller and all 21 control lines. Bench-driven = the golem pulse. Not in the file: the station, zombies' farm, beds, the scheduler; farmopt's pad not yet wired.
- **Tolerance** (ironfarm's sweeps, bench-driven with these times and a stand forced to deliver, at-rest check, one control at a time; t0-relative):
  - release end − 10..+ 16; S1 − 6..+ 3, S2 − 2..+ 6, S3 − 3..+ 6; tail slot 1 − 3..+ 2, slot 0 − 2..+ 3; slot 2 + 92..+ 114 (wired + 100: − 8..+ 14);
  - corners: every control at its early limit together, then every one at its late limit together: both pass;
  - **flags:** advance 2's width with 12-gt pulses − 3..0 (0 late; v2 shapes the pulses to 10 gt); the stand brake, the 2-tick catch: redstone + 28 only (0 either way; farmopt's stop-based stand replaces it).
