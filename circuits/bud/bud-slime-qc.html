Details: how it works in depth, our test in the real game, measurements and properties

In depth

A block change detector (players call it a BUD switch, for block update detector) fires its output when something happens at its target cell, next to it, although nothing there powers it. The judge tries five kinds of change at the target, three times each: place (a block placed), remove (removed), state (the block changes state), shape (a change that sends shape updates only, the way crops grow) and update (a block update next to the target with nothing changing). Each detected change must give exactly one output pulse, and nothing may fire in between.

This design detects place, remove, state, update; it does not see shape.

Each detection gives a 1 gt (0.05 s) output pulse, 3 gt (0.15 s) after the change. It can detect the next change 6 gt (0.3 s) later (re-arm). Two changes close together jam it: update pair 2 gt apart.

The simpler 2-block BUD switch (a sticky piston and a redstone block) latches until you reset it; for visible block changes a single observer is enough.

Notes from its designer

The classic BUD: it sees blocks placed, removed or changed next to the target and pure block updates, which no observer can see: the smallest, 3 blocks. A sticky piston under a slime block and a redstone block is powered without having noticed it (the power reaches it only through the block above it, called quasi-connectivity); the first update makes it notice and lift the redstone block past the output for a moment, then pull it back, armed again. Detail: the landing slime block updates the piston through its head so it retracts, the redstone block landing last, so it re-arms without an update. A change by shape alone sends no block update: not detected; two updates 2 ticks apart jam it.

# archived 2026-10-20T11:05Z from designs/circuits/tracks/bud/bud-slime-qc.txt by mctas circuit archive
# CIRCUIT: bud-slime-qc bud detects place remove state update, latency 3 gt, pulse 1 gt, re-arm 6 gt, jams update pair 2 gt apart, footprint 5 cells, tileable every 2 (0 0 2), 3 blocks, 1x4x1, robust
name: bud-slime-qc
circuit: bud
tile: 0 0 2
# The observer-free BUD, armed by quasi-connectivity: a sticky piston facing up under a slime block
# and a redstone block. The redstone block powers the piston only through the cell above it, and
# nothing updates the piston when that power is there, so it sits armed until a block update
# reaches its cell (a block placed, removed or changed beside it, or a pure update). Then it extends:
# the slime block lifts the redstone block beside the output for 1 gt, where it no longer powers the
# piston; the landing slime block updates the piston through its head, it retracts and pulls both
# back, the redstone block landing last, so the piston is armed again without an update. A
# shape-only change sends no block update: not detected. Two updates 2 gt apart jam it.
origin: 0 0 0
port target: 1 0 0
port output: 1 3 0
