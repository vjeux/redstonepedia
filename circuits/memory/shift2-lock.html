In depth

a row of memory cells: each clock pulse moves every bit one step along, so the data comes out a set number of clock pulses later

How to try it

Press play under the view to watch the judge's own test on a loop (the badge reads demo with the step it is on; the same test is drawn as a timing diagram below). Touch any control to stop it and try the circuit yourself.

To try it: press and hold the CLK button of the bar (or the cell tagged CLK) to power that input; a quick tap sends a short 2 gt pulse; press and hold the D button of the bar (or the cell tagged D) to power that input; a quick tap sends a short 2 gt pulse.

Inputs are tagged in lime; the output is tagged OUT: the redstone lamp in that cell (the lamp the judge itself adds to read the output) lights while the output is on (the output strip by the demo badge shows its last 40 game ticks, 2 seconds). Drag to look around, pinch or scroll to zoom, step one game tick at a time with the step button.

Measurements

Measured in our test in the real game, facing all 4 ways at 4 spots in the world. gt = game tick = 1/20 s (20 gt = 1 second).

metricvaluewhat it means
N2the delay: how much later the output copies the input
latency6 gt (0.3 s)the worst time from an input change to the output's change
edgerisingwhich input edge flips the output: rising = the input turning on, falling = turning off

Notes from its designer

2-bit shift register, 27 blocks: two repeater-lock flip-flops in a row, the first stage's output feeding the second stage's data. The first stage reads the clock block directly (its master lock behind it, its slave's wall torch hanging on it); a dust on top of the clock block carries the clock round to the second stage's stone, which plays the same part for it. On each rising edge both stages shift at once.
