Clock

every 450 ticks (22.5 s) · 42 blocks

Its output pulses by itself every 450 ticks (22.5 s), forever. It starts on its own once built.

A lamp on its output stays lit: the output is off for only 2 ticks (0.1 s) at a time, and a redstone lamp goes dark only after more than 4 ticks (0.2 s) without power. Redstone dust there follows every pulse.

made of comparator, redstone torch, redstone wire · on for 448 of 450 ticks

extended (n = 6)starts by itself

every 450 ticksClock3D view loading (or not available in this browser)

A longer version of the tested clk-rt-fade clock, which pulses every 114 ticks (5.7 s) with 18 blocks; this one is 6 steps longer (n = 6). Each step: add one compare-mode comparator to each row of the comparator fading ring (2 + 2 comparators at n = 0, a lossy two-dust turn, a refill torch), which adds 56 ticks (2.8 s) and 4 blocks. Tested in the real game too.

Every clock that pulses every 450 ticks (22.5 s): on the Clocks tab, smallest first (the ones hard to wire into a circuit last).

Try it

It runs by itself: the view plays it; pause and step one tick at a time with the buttons under it. To use it in a circuit, put a repeater where the view puts its lamp: it picks up every pulse.

How this design does it: EXTENDABLE comparator fading ring, n = 0 (P = 114 + 56n): Comparator FADING ring (clk-rt): two dust (one level lost per lap) -> top row [comparator, comparator] -> block F -> dust beside F (a wall torch on F lights when the ring is empty and refills it through a dust beside it) -> bottom row [comparator, comparator] -> back; the compare-mode comparators keep a signal strength, each dust-to-dust step loses one level per lap, and the torch refills the ring at 0

Its output over time

The output (orange) over the first 916 ticks, as the 3D view plays it: the grey part is the clock starting up, for 16 ticks (0.8 s); then it repeats every 450 ticks (22.5 s), on for 448 ticks (22.4 s) of them. 20 ticks = 1 second.
