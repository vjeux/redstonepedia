every 31 ticks (1.55 s) · 20 blocks

Its output pulses by itself every 31 ticks (1.55 s), forever. Built in the game it needs one kick to start (the last block placed); then it keeps going.

made of repeater · on for 8 of 31 ticks

extended (n = 1)

every 31 ticksClockpicture from the real game; the live 3D view replaces it when available

A longer version of the tested clk-rt-odd-rect clock, which pulses every 23 ticks (1.15 s) with 16 blocks; this one is 1 step longer (n = 1). Each step: lengthen the 3 x (4+n) ring (delay-4 repeaters, one delay-3, corner blocks) by one row: one more repeater on each long side; two pulses 23 + 8n gt apart, the second started by a temporary torch at an odd tick, which adds 8 ticks (0.4 s) and 4 blocks. Tested in the real game too.

Every clock that pulses every 31 ticks (1.55 s): on the Clocks tab, smallest first (the ones hard to wire into a circuit last).

Try it

The view starts it for you, then it runs by itself: pause and step one tick at a time with the buttons under it. To use it in a circuit, put a repeater where the view puts its lamp: it picks up every pulse.

How this design does it: EXTENDABLE odd two-pulse ring, n = 0 (P = 23 + 8n): Rectangle ring (clk-rt): the 3x4 perimeter clockwise from the north-west corner = [b, 4*, b, 4, 4, b, 4, b, 4, 3] (number = repeater delay, * = powered at placement, b = block, d = dust, T = wall torch on the block before it, c = comparator); 0 torches: a pulse ring of loop delay 46 gt; the second pulse started by a redstone_wall_torch[facing=south,lit=true] at [0, 0, 3] for 1 gt at tick 1 (an odd tick)

Its output over time

The output (orange) over the first 102 ticks, as the 3D view plays it (the design names no output, so this is its repeater that turns on most often): the grey part is the clock starting up, for 9 ticks (0.45 s); then it repeats every 31 ticks (1.55 s), on for 8 ticks (0.4 s) of them. 20 ticks = 1 second.
